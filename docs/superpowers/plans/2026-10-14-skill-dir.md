# skill-dir Implementation Plan

**Goal:** Kein Skill ruft ein Skript mehr repo-relativ auf; jeder Aufruf steht in der
SKILL.md als `python "${CLAUDE_SKILL_DIR}/scripts/…"`, die Hook-Vorlagen kopieren ihr
Skript nach `.claude/hooks/` und melden ein fehlendes, und `script-paths` in skill-forge
hält das.

**Architecture:** Umstellung je Plugin-Gruppe, dann die Lint-Regel, damit das Register in
`tests/test_skills_lint.py` nie wächst. architecture-map schreibt eine stabile Herkunft
(`python scripts/<datei> …`), die `drift_check.py` gegen den eigenen Skill-Ordner auflöst.

**Lesson aus Spec 22 D:** Vor dem Push die Suite in einem frischen Worktree fahren, nicht
im Arbeitsverzeichnis — ignorierte Dateien verdecken dort fehlende.

**Tech Stack:** Python 3.11+ Stdlib; Markdown; JSON-Hook-Fragmente.

**Spec:** `specs/Spec 25 – skill-dir.md`

## Global Constraints

- **E1 — Ersetzung:** `skills/<name>/scripts/<datei>` → `"${CLAUDE_SKILL_DIR}/scripts/<datei>"`,
  fremde Skills `"${CLAUDE_SKILL_DIR}/../<name>/scripts/<datei>"`; immer mit `python` davor.
- **E2 — Kontrolle je Skill:** `lint_skill.py skills/<name>` ohne `--base` zeigt keinen
  Aufruf mehr (der Prototyp aus der Spec); `--base HEAD~1` für `evals_due`.
- **E3 — Projekt-Kopien** über `python scripts/sync_skills.py`, `--check` ohne Abweichung.
- **E4 — Gate-Sprache:** `script-paths` G2; Hook-Vorlagen bleiben G3.
- **E5 — Anti-Zeremonie:** Eine Skill ohne Skripte bekommt `script-paths: pass`.
