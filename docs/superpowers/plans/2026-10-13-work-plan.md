# work-plan Implementation Plan

**Goal:** In einem Repo außerhalb dieser Sammlung entsteht aus einer feature-spec-Spec,
einem Befund oder einem Auftrag ein Plan, den subagent-dev lint-sauber liest und der mit
der Verifikation des Repos endet — und kein Verweis zeigt mehr auf
`superpowers:writing-plans` oder `superpowers:subagent-driven-development`.

**Architecture:** Tier 1 ohne eigenes Skript: work-plan ist Doktrin (SKILL.md, eine
Reference, ein Template) und ruft den Lint von subagent-dev über
`${CLAUDE_SKILL_DIR}/../subagent-dev/scripts/plan_to_tasks.py` auf. Der einzige Code liegt
in `plan_to_tasks.py`: Es akzeptiert die Kopfzeile `skill: work-plan` und prüft dafür
Quelle, letzten Task `Verifikation` und die Coverage gegen feature-spec-Kriterien. Dazu
die Verweise in fünf Nachbar-Skills, README und Spec 00 und `docs/plans/` als
Hausartefakt im Bereichs-Hook von setup-repo.

**Lesson aus Spec 22:** Ändert sich ein Asset, das Fixtures byte-gleich kopieren
(`goal_scope.py`), gehören die neu erzeugten Fixtures in denselben Task.

**Tech Stack:** Python 3.11+ Stdlib für Lint und Tests; Markdown für Skill, Reference,
Template, Evals.

**Spec:** `specs/Spec 23 – work-plan.md`

## Global Constraints

- **E1 — Tier 1 ohne eigenes Skript.** work-plan besitzt den Lint nicht; jede
  Format-Erweiterung entsteht in `plan_to_tasks.py` und ist dort getestet. Fehlt das
  Skript, heißt die Übergabe „ungeprüft — Lint nicht verfügbar".
- **E2 — Gate-Sprache:** Zeigen des Plans G1, Lint G2; nichts nennt sich härter.
- **E3 — Kopfzeile:** Pläne `skill: work-plan` in Zeile 1; das Template trägt sie.
- **E4 — SKILL.md ≤ 150 Zeilen**, portables Frontmatter.
- **E5 — Anti-Zeremonie-Eval** `anti-ceremony-one-file-change-gets-no-plan`, gebunden an
  `output_matches` und `file_absent`.
- **E6 — impl-plan-Regeln bleiben unverändert;** jeder bestehende Plan-Lint-Test bleibt
  grün.
